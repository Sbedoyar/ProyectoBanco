## OmniSpec 0.7.0-preview.2
Use the project's OmniSpec workflows for requested engineering work. Start with omni-init to understand the project or omni-discuss for exploration. Read CONSTITUTION.md, specs/project-context.md and CLI status --json; use its blockers and next action when resuming. Compare the CLI version with the project's manifest before acting. Inspect before asking; use available native question tools or the current chat/console and respect existing answers. Record actual session capabilities and approval/delegation for material decisions; verify technology choices against dated official sources. Preserve language-appropriate API documentation and the agreed commit convention. Reconcile stale context before context-record and inspect effective capability contracts when changing existing behavior. Included guide setup/design/evidence resources support preparation and contextual UI without requiring external skills. UI work requires relevant references and actual rendered/interaction checks with typed evidence; no universal visual recipe or first-attempt guarantee. Documentary audit is not code verification; automated criteria require checkIds or unambiguous checkCommands bound to executed configured checks. Assertion adequacy, observed manual evidence and semantic truth require review. Keep work within the user's authorization, including any local-only restriction.
Run the OmniSpec CLI with `node specs/.omni/runtime/bin/omni-spec.mjs` (or global plugin CLI `omni-spec` / `npx omni-spec`).
